# 0007 — The fork keeps its own changelog

Date: 2026-10-24 · Status: accepted

## Context

Upstream stash has a changelog: one file per release in `ui/v2.5/src/docs/en/Changelog/`,
shown in the app. It records upstream's changes and arrives with every upstream merge. The
fork's changes are a different history on a different schedule, with no releases, and
nothing recorded them except commit subjects.

## Decision

Two changelogs that never mix:

- `FORK_CHANGELOG.md` holds the fork's changes, generated by `scripts/changelog` from the
  fork's conventional-commit subjects (commits not reachable from `upstream/develop`),
  grouped by day. Each upstream merge is one line, with how many upstream commits it
  brought and a pointer to upstream's changelog.
- Upstream's in-app changelog is never edited by the fork. Adding fork entries there would
  conflict on every merge, and would show fork changes as if they were upstream releases.

## Consequences

- Commit subjects are the changelog, so write them for a reader:
  `feat(ui): add a Collections display mode for the scene list`, not `wip`.
- The file trails each commit until it's regenerated. `scripts/check` warns rather than
  fails on that.
- `.claude/hooks/guard-files` asks before an agent edits upstream's changelog.
